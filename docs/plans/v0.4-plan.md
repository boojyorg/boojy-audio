# v0.4.0 — Visual & UX Polish

> The first dedicated UI/UX pass for Boojy Audio. Scoped from the
> [2026-05-30 UI/UX review](../reviews/ui_ux_review_2026_05_30.md) (48-bug ledger, 4-DAW
> comparison, design direction, ASCII mockups + the §11 v0.4 brainstorm). This plan is the
> living spec; the review is the evidence behind it.

## The goal in one paragraph

Boojy works but feels *generic and slightly off* — a C+ look. The review traced that to five root
causes, not a pile of unrelated bugs: a mixed warm/cool palette, no bundled typeface, no type-scale
control, heavy hardcoded-colour leakage, and inconsistent button shapes. v0.4 fixes the **feel**:
one calm "deep-space" look, a real typeface, readable type at any display size, then a few
high-impact surface re-treats, and finally the top-bar redesign tried live as an A/B. No new audio
features — this is purely how the instrument looks and reads.

## Design anchors (Tyr)

GarageBand (approachable, tablet/mobile-ready) · FL Studio (piano roll) · Ableton (effects /
wet-dry) · Logic (premium but simple). Space theme = **distinctive but restrained**. Principle:
**"everything useful on the page"** — favour on-page surfaces over panels that pop out and shuffle.

## Sequence

Foundation must land first so the later A/B is judged on the finished look.

### ✅ Phase 0 — Quick-win bug batch (was PR #21, folded into v0.4.0)
Version label, About box, start-screen Settings button, zoom-out icon, tempo clamp (20–300),
velocity-lane colour, clip-colour palette, loop-hint contrast. *(No separate v0.3.3 tag — we
skipped straight to v0.4.0.)*

### ✅ Phase 1 — Foundation (this slice)
- **Typefaces:** bundle **Inter** (UI) + **JetBrains Mono** (numeric readouts) as OFL `.ttf`;
  `ThemeData.fontFamily = 'Inter'`, `BT.fontFamilyMono = 'JetBrainsMono'`.
- **Palette:** retune the dark ramp to one near-neutral **"gunmetal"** dark-grey family (faint cool
  undertone) so chrome (top bar, sidebar) joins the content tone instead of the old warm `#2C2C32` —
  without a navy cast. Accent blue unchanged. Dark theme only this pass. **Graphite / Slate /
  Indigo** ramps remain as live A/B presets in the `Cmd+Shift+P` palette dev tool (Gunmetal was
  chosen as the default after a live A/B).
- **UI Scale:** a persisted **Settings → Appearance → UI Scale** control (Compact 0.90 / Default
  1.00 / Comfortable 1.10 / Large 1.20) applied globally via `MediaQuery.textScaler`. Default 1.0 =
  no change out of the box. `BT.scaled()` helper added for painters (which don't auto-scale).
- **Elevation tokens:** `BT.shadowColor` / `elevation*` / `shadowSm·Md·Lg`; deeper, cooler shadows
  on menus + tooltips.

**Known follow-on:** at Comfortable/Large, dense fixed-height bars (e.g. the top bar, already
overflow-prone — B8) may tighten/clip until Phase 2/3 makes them flex. Expected, not a blocker.

### ✅ Phase 2 — Contained re-treats (PR #23)
- **Piano roll:** replace the grey key lanes with an indigo lane treatment + a subtle root-note
  band (B5).
- **Time readout:** Bars → Time → Both toggle with a readable seconds display (`0:05.12`),
  persisted, with a pinned ruler overlay (B6).
- _Shipped as:_ accent-blue (not indigo — the navy ramp was dropped for gunmetal) keyboard-contrast
  lanes + root band + hover active lane; the Bars→Time→Both readout cycle + a pinned orientation
  chip. Lane **colours** flagged for a post-Phase-3 refinement.

### 🟡 Phase 3 — Top bar, tried live (LAST) — _A & B + title fix shipped (PR #26)_
- Build **all four** top-bar layout variants (A one-row hero / B LCD panel / C two-row /
  D arrangement-hero — see review §11) behind a **dev-tools "UI Labs" switcher** so Tyr can feel
  them on the finished look rather than choosing on paper.
- Fold in the proper **macOS title-centring fix**: hide the native title
  (`window_manager` `TitleBarStyle.hidden`, keep traffic lights) and draw a centred title in
  Flutter. *(No native `NSToolbar` style is both centred and compact — see review B2.)*

**Status:** macOS title fix ✅ (native bar hidden, transport bar runs edge-to-edge; left group insets
to clear the traffic lights). UI Labs switcher ✅ (`Cmd+Shift+L`, debug-only, choice persists via
`UserSettings`). Variants **A · inline** ✅ and **B · LCD panel (68px)** ✅. Centred-title slot wired
but **off by default** — it collides with the transport controls in single-row variants, so its form
is settled live (cleanest in C). **Remaining:** Variants **C** (two-row) & **D** (arrangement-pinned
LCD), the centred-title decision, then the piano-roll lane-colour refinement.

## Explicitly deferred (own sessions)
- The **~390 hardcoded-colour tokenisation sweep** (B15/B16) + light / high-contrast ramp retune —
  must precede any serious light-theme work.
- **Effects / device-panel overhaul** — universal MIX (wet/dry) knob, gain-reduction meter, EQ
  dot-curve; needs engine FFI. Tyr's effect priorities: perfect EQ / Compressor / Reverb / Delay;
  drop Chorus / Limiter for now.
- **Serum / VST3 load bug** — separate investigation.

## Open design questions (resolve during the phase they touch)
- Top-bar hero readout placement — which of A/B/C/D wins the live A/B.
- Mixer: vertical faders + "all useful stuff on one page" — bottom-dock vs right-dock; track
  identity via a coloured name header shared with the arrangement.
- Effects forks — is the GarageBand 3-dot curve the EQ default, and does a MIX knob belong on EQ.

relaunch; menus/tooltips have deeper shadows. Gates: `flutter analyze --fatal-infos`,
`flutter test`, `dart format --set-exit-if-changed`.
