# v0.5.2 — Correct on real hardware, right after undo

> Scoped from the [2026-06-05 codebase audit](../reviews/codebase_review_2026_06_05.md) (41
> adversarially-confirmed bugs) and [Tyr's triage](../reviews/triage_2026_06_05.md). This is a
> **correctness-only** cycle — no features, no visible UI change. The split rule from triage:
> *invisible correctness* lands here; *user-visible change* (UI ledger, mockups, Join clips)
> waits for v0.6. Absorbs the old "loop & device polish" scope deferred from v0.5.1.

## The goal in one paragraph

Today the app is solid on the dev machine's happy path and quietly wrong everywhere else. Drag a
clip and press Cmd+Z: the UI snaps back but the audio still plays from the new position — every
time, not an edge case. Edit effects while stopped (the normal workflow) and the UI can freeze
silently. Save can report success while having failed; reload can silently drop clips and held
notes. And on the 44.1 kHz interfaces most musicians actually plug in, every delay, reverb, and
recording is ~9% off. v0.5.2 makes undo honest, saving honest, and the engine correct on real
hardware — and stands up the first engine `api`/`ffi` tests so it stays that way.

## Design decisions

- **Many small PRs, not one branch.** Each phase below is a separately mergeable PR with gates
  green. Cost: more PR overhead. Benefit: a regression bisects to a small diff, and the cycle can
  stop early at any phase boundary if v0.6 pressure builds.
- **Criticals first, hardware last.** The two criticals are S-effort and hit every session; the
  sample-rate sweep is the L-effort item. Per triage, the sweep is **the designated split-out** —
  if the cycle needs to slim down, Phase 8 becomes v0.5.3, and nothing earlier depends on it.
- **Tests land in the same cycle as the fixes** (Phase 7 before Phase 8): the save/reload and
  undo/redo round-trip tests lock in Phases 1–4 before the riskier engine-wide sweep starts.
- **Adjacent undo bugs are if-time, not in-scope.** The audit found more undo holes (C45/C47/C48
  etc.) than triage explicitly assigned. They fit the theme, but scope discipline wins — they're
  listed under *If time allows* for an explicit call, not silently pulled in.

## Phases (each = one small PR, gates green between)

### Phase 1 — The two criticals + sampler fix

- **C32** — stopped-path lock-order inversion: `renderer.rs` takes effect→track, `api/effects.rs`
  takes track→effect → silent UI deadlock on add/remove-effect while stopped. Align the order (or
  snapshot under one lock).
- **C46/C63** — MIDI clip move/undo never updates the engine start time: route
  `MoveClipCommand.execute()/undo()` through `rescheduleClip`/`setClipStartTime`.
- Cherry-pick the **sampler blank-panel fix** (`6df5ac6`, stranded on
  `fix/v0.5.1-sampler-instrument-create`).

### Phase 2 — Honest saves, faithful reloads

- **C55** — `saveProjectToPath` reports success on engine `Error:` and repoints auto-save at the
  corrupt path. Gate on the `Error:` prefix (the load path already does).
- **C61** — `saveProjectAsCopy` silently redirects the project path to the copy (live on web).
- **C65** — held MIDI notes silently dropped on save (flush `active_notes` at end-of-clip).
- **C66** — audio clips silently dropped on reload when a track has >1 clip / a moved asset;
  surface a real load error instead of `eprintln!`-and-continue.

### Phase 3 — No stuck notes, no clicks

- **C38** — PianoRoll `dispose()` never sends NoteOff for the held audition note.
- **C41** — chord-preview delayed NoteOff fires after dispose; chord voices untracked.
- **C7** — synth release anchors to `params.sustain`, not level-at-note-off → click on every
  staccato note (sampler already does this right — copy its approach).
- **C10** — voice steal hard-cuts voice[0] with no ramp (synth + sampler).

### Phase 4 — Export tells the truth

- **C16** — "Export for Spotify/…" LUFS platform-target is dead code — applies nothing.
- **C18** — export range (`start_time`/`end_time`) silently ignored; always renders from 0.
- **C68** — stems apply fader *before* FX, full mix applies it *after* → stems ≠ mix.

### Phase 5 — FFI boundary hardening

- **C33** — null-guard `CStr::from_ptr` in `create_track_ffi`, `add_effect_to_track_ffi`, `sends.rs`.
- **C34** — track-name comma injection shifts every CSV field in `get_track_info` (escape or
  re-delimit; fix both Rust emit and `TrackData.fromCSV`).

### Phase 6 — Local gates = CI, release hygiene

- **C76/C77** — post-edit hook runs clippy without `-D warnings` and analyze without
  `--fatal-infos` — green locally, red in CI. Align.
- **C78/C79** — commit `Cargo.lock` + `pubspec.lock` (binary crate + app: both belong in git).
- **Appcast edSignature double-wrap** (pre-existing, since v0.1.4) — `release.yml` emits
  `sparkle:edSignature="sparkle:edSignature=…"`, likely breaking Sparkle auto-update for every
  release. One-line fix in the signing step.

### Phase 7 — Engine test net, first slice (C69)

`engine/src/api/` + `ffi/` currently have **zero** unit tests. Not full coverage — a beachhead:

- **Save → load round-trip fidelity** (locks Phase 2: clips, held notes, multi-clip tracks).
- **Command execute → undo → redo round-trip** against engine state (locks Phase 1's C46/C63
  class of bug).
- **Export smoke** (locks Phase 4: range honored, LUFS applied, stem == mix gain order).

### Phase 8 — Real hardware (the designated split-out → v0.5.3 if needed)

- **Sample-rate sweep** (C2/C9/C4/C6/C11/C22/C26 + C21/C62): working `set_sample_rate` on
  Delay/Chorus/Reverb/VST3Effect, buffer resize, recorder duration, monitoring ramp, filter
  mapping, VST3 block-size on reload. One root cause (hardcoded 48 kHz), eight expressions.
- **Carried v0.5.1 device items:** metronome downbeat doubling at loop wrap (per-beat
  last-fired guard); MIDI keyboard hot-plug (midir input not re-connected on re-enumeration —
  needs real hardware); **C99** device disconnect kills playback silently; **C104** output
  device not persisted.

## If time allows (explicit call, not silent scope creep)

Adjacent audit finds that fit the theme but weren't triaged into v0.5.2: **C45** (delete-undo-redo
ghost-plays a stale clip ID), **C47** (duplicate-track undo leaks clips/windows), **C48**
(recording-undo restores only startTime), **C49/C54** (reorder / sampler-drag not undoable),
**C52** (stale effectId on param undo), **C17** (quantize ignores division), **C40/C71** (non-4/4
loop-follow + count-in), **C81/C83/C87** (release-pipeline hygiene Lows).

## Out of scope (deliberate)

- **Everything user-visible** — Calm & Legible UI ledger, §6 mockups, dogfood-notes items → v0.6.
- **C37/C50** (consolidation bypasses undo) — subsumed by v0.6's Join-clips rewrite; fix once.
- **VST3 fidelity** (C27/C28/C29/C30) — its own later cycle, after this test net exists to catch
  C++ regressions.
- **High Contrast theme hiding** — open question in triage, UI-facing → v0.6 conversation.

## Verification (manual, per phase — on the real app)

1. Stop playback → add/remove an EQ repeatedly → no freeze. Drag a MIDI clip to a new bar,
   Cmd+Z, press play → audio comes from where the clip *is*, both before and after undo.
2. Move a clip's `.wav` out of the project's audio folder → reload → an error message, not a
   silently empty track. Record a long held note → save → reload → the note is still there.
3. Tap a key for <100 ms → no click. Click a note in the piano roll, instantly close the editor
   → no stuck note. Hold sustain + mash 10+ keys → no hard click on voice steal.
4. Export with a platform target → measure ≈ −14 LUFS. Export stems and full mix with a
   compressor on a track → stems sum sounds like the mix.
5. Rename a track to `Vocals, Lead` → mixer/inspector still show the right type and volume.
6. Add a `print()` to a Dart file → the post-edit hook goes red locally (same as CI).
7. `cargo test` covers api/ffi round-trips; suite green.
8. Set the Mac output device to 44.1 kHz → a 500 ms delay echoes at 500 ms (not 544); record a
   clip → plays back at correct pitch/speed. Plug in a MIDI keyboard mid-session → notes flow.
