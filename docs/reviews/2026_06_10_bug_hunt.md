# Boojy Audio v0.6 — Bug-Hunt Report
*Synthesized 2026-06-10 from 70 confirmed findings (2 adversarial verification passes each) across 18 areas. "Seeded" = you observed the symptom yourself in dogfood.*

---

## 1. Verdict

**Overall: the app's core is sound, but the two headline v0.6 features — drum kit and sampler — are shipping broken in ways a first-time user hits immediately, and there is one engine-level timing bug that silently corrupts every project not at 120 BPM.**

The undo system, save/load, FFI layering, and export pipeline all held up well under adversarial review. What didn't: the *integration seams* — clips created but never told to the engine, UI values that never cross the FFI boundary, selection state set on one path but not its three siblings.

**Must fix before tagging v0.6** (the "Sound" release can't ship with its sound features broken):

1. **Sampler produces silence on Play** — the default clip is never scheduled in the engine. The sampler *looks* installed and is completely dead.
2. **Sampler has no way to hear a note** without discovering the hidden MIDI tab.
3. **Audio clips play at the wrong time at any tempo ≠ 120 BPM** — engine applies a tempo ratio to audio clips but not MIDI, so the two clip types desync. This is data-corrupting in effect, not polish.
4. **Drum kit: playhead highlights the wrong column** whenever the clip isn't at bar 1, and **drag-to-paint doesn't exist** (16 clicks for a hi-hat roll).
5. **Collapsed editor bar crashes on a phantom "Effects" tab** for plain MIDI tracks (debug assert / release state corruption).
6. **Right-click is dead in debug builds** on library items and project cards (`context.colors` listen-in-handler — the v0.5.1 bug class, again).

Everything else — visual sweeps, undo gaps, persistence holes — is real but can ride a v0.6.x patch.

## 2. Ranked Bug Ledger

**Root-cause clusters (one fix, many symptoms):**
- **Cluster A — tempo time-domain:** renderer `tempo_ratio` on audio clips + missing engine sync on tempo change + same gap in tempo undo. Three findings, one design flaw: audio clips and MIDI clips live in different time domains.
- **Cluster B — clip-creation skips selection:** drum kit, sampler, audio→sampler convert, and the drop-clip race all miss `autoSelectClip: true` that the synth path has. Four findings, one missing argument.
- **Cluster C — Provider listen:true in event handlers:** library menus (×2), project card menu, sampler root-note dropdown. Four findings, one sweep (documented bug class from v0.5.1).
- **Cluster D — Border.all + borderRadius + clipBehavior corner artifact:** project card, drum-kit waveform block, Loop + Snap split buttons. The exact anti-pattern in `.claude/rules/flutter-ui.md`, partially fixed in PR #83.
- **Cluster E — drum playhead math:** `_currentStep` ignores `clip.startTime` (reported twice) and `contentStartOffset`. One formula fix.
- **Cluster F — time-signature denominator:** dropped at FFI (reported in Dart + Rust), plus piano-roll Signature control is UI-local-only, plus ruler hardcodes beatsPerBar=4. The whole time-sig feature is display-only theater.

## 3. Fix Batches

**Batch 1 — "The sampler makes sound"** *(sampler-blocking, Tyr's #1)*
Schedule the default clip in the engine on creation (#1), add an in-tab audition strip or reorder tabs (#2), `mounted` guard after file picker (#22), root-note dropdown listen:false (#23). One PR, sampler goes from dead to usable.

**Batch 2 — "Time is one domain"** *(engine correctness; quietly the worst bug in the app)*
Unify audio-clip time domain in the renderer (#3), push rescaled clip positions to the engine on tempo change + undo (#4 + ledger Cluster A), resync metronome phase on live tempo change (#28). Then the time-signature decision: either pass the denominator through FFI (#18 + wire piano-roll Signature #10) **or** make the denominator read-only 4 in the UI for v0.6 — shipping a control that does nothing is worse than not shipping it. Ruler `beatsPerBar` passthrough (#11) is a one-liner either way.

**Batch 3 — "Drum kit feels finished"**
Playhead formula: clip-local beats with startTime + contentStartOffset (#5 + cluster E), drag-to-paint with paint/erase mode from first cell (#6), `autoSelectClip: true` across all four creation paths (Cluster B: #13, #20, #21), pad fader/mute/solo undo (#25), waveform-block corner artifact (Cluster D item).

**Batch 4 — "Right-click works, Favorites work"** *(debug-blocking + library)*
Provider listen-in-handler sweep (Cluster C: #8, #23 if not done, #55, library ×2 — grep the whole repo for `context.colors` in handlers, this class has now shipped three times), Favorites searches folder cache + VST3 (#9), star icon pair + facade fix, `revealInFinder()` helper in native_dialogs for Windows (#40), path-as-ID (#41), phantom Effects tab (#7 — small, ride here), 60px scroll buffer (#12 — one line, ride here).

**Batch 5 — "Undo tells the truth, projects remember"**
RecordingCompleteCommand offset/duration + MIDI engine resync (#15, #16), SetTrackIconCommand + icon persistence (#17, #47), sampler parameter command (#24), auto-save restart + surface or delete the undo-limit setting (#44, #45), navBar controller dispose (#52), delete the dead command stubs.

*(The visual Low sweep — corner artifacts, radii, dividers, button tokens, hover states — fits the existing dogfood-batch rhythm as batch 6 / v0.6.x polish and shouldn't gate the tag.)*

## 4. Unresolved Seeded Leads — need your eyes

These are symptoms **you observed** where the hunt either failed to root-cause or the verifiers split. Manual repro / a decision needed:

1. **Wordmark baseline shift** (start screen) — verifiers split on whether `PlaceholderAlignment.middle` at `boojy_wordmark.dart:125` actually shifts the baseline. Look at the start screen at 1× and 2× scaling; if you still see it, it needs a render-level investigation, not a grep.
2. **Mixer strip asymmetric border (4px left / 2px elsewhere)** — code comments say intentional ("like Master track"), but it conflicts with your "one border treatment" theme. Decision, not bug.
3. **New audio tracks arm by default and don't disarm others** — the engine *deliberately* supports multi-track audio recording (per-channel capture). One verifier calls it a feature, one a bug. Decide the beginner-first behavior: exclusive arm like MIDI, or keep multi-arm with clearer UI?
4. **M/S/R/I tap delay (~100–400ms)** — verifiers split on gesture-arena cause. Note: batch 2's lock fix (#19) is the *other* candidate root cause for sluggish toggles — re-test after that lands before chasing the gesture arena.
5. **Automation readout shows fader position, not live curve value** — confirmed behavior, but there's no engine API to query the interpolated value, so it's a feature gap, not a wiring fix. Defer or scope.
6. **Sampler Warp controls** — the "no playback" framing was refuted (covered by Batch 1), but buried in the refutation both verifiers **confirmed Warp/warp-mode are stored and never read by the audio path** — the controls are pure no-ops. Either wire them or hide them for v0.6; don't ship dead knobs on the headline feature.
